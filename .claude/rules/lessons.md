# Грабли, которые уже стоили дня

Индекс узнавания, не архив: три строки на запись, детали — в атоме mIOnika,
чей ID стоит в скобках (`projectId: "bunch-package"`).

Этот файл грузится всегда: здесь только то, что нужно в любой сессии. Уроки одной зоны — в
`lessons-<зона>.md`, Claude Code подгружает их, когда работа идёт с файлами этой зоны.

## Паспорт (читает skill `lesson`)

- **Первоисточник:** mIOnika, `projectId: "bunch-package"`. `note` — измерение (симптом → как
  воспроизвели → числа → вывод); `insight` — урок о том, как мы работаем. `trustStatus: verified`
  для измеренного, `pending_review` для гипотезы. Связь — с задачей, в которой всплыло.
  Родитель в дереве — не задан. Задача из урока — с тегом модели (`.claude/rules/mionika.md`).
- **Урок меняет способ работы** — обновить и правило: порядок доказательства → `skills/verify`,
  выпуск → `skills/release`. Строку в горячий минимум `CLAUDE.md` — только предложить.
- **Бюджет:** 20 записей на файл, 3 строки на запись. Запись уходит, когда повтор стал
  невозможным (тест, корпусный прогон, проверка в CI), а не когда «починили».
- **Превышение:** в этом файле 25 записей при бюджете 20 — новые сюда только с вытеснением.
- **Зоны (файл ← paths):**
  - `lessons-patch.md` ← `src/hunks.ts`, `src/patch-file.ts`, `src/plan.ts`, `src/binary.ts`, `src/import.ts`, `src/export.ts`, `src/fold.ts`, `src/apply.ts`, `src/create.ts`
  - `lessons-bun.md` ← `src/create.ts`, `src/edit.ts`, `src/paths.ts`, `src/presence.ts`, `src/shared.ts`, `src/workspace.ts`, `src/lock.ts`, `src/apply.ts`, `src/annotate.ts`, `src/upstream.ts`
- Урок про метод, тесты и корпус, процесс, выпуск и использование графа — здесь: эти действия не
  открывают файлов зоны, и зональный файл в контекст не попадёт.

## Молчаливый провал — самый дорогой класс здесь

**Правка файла в `node_modules` меняет запись глобального кеша bun.** На Linux
hardlink — умолчание, инод общий с кешем; следующая чистая установка в другом
проекте приезжает с чужой правкой. Перед правкой — `edit`. (NOT-2, NOT-18)

**Путь обработки сбоя был мёртв три релиза.** `firstDiagnosticLine` вызывалась и
не была определена: запасной путь через npm летел `ReferenceError` вместо
отката. Такие пути тестируются нарочно — сами они не исполняются. (INS-5)

## Формат патча: чужие данные не такие, как в голове

**Скоуповых пакетов не касался ни один тест**, хотя это половина экосистемы: две
мутации из четырёх, переживших зелёную сюиту, были ровно про них. (INS-7)

## Чем доказываем

**Зелёная сюита говорит только, что никто не сломал проверяемое.** Что вообще
проверяется, показывает мутация: 23 снятых защиты, 19 пойманы, 4 пережили. (INS-7)

**Выжившая мутация — не всегда лишний код.** Дважды это был тест, проходивший
случайно: из-за порядка `readdirSync` и из-за второго замка на той же двери.
Проверять не только код, но и причину, по которой тест зелёный. (INS-9)

**Многохунковый патч в сюите всегда был про разные файлы.** Двух хунков в одном
файле не клал ни один тест из 228: снимаешь накопленный `+ offset` — сюита
зелёная, а патч молча правит не тот из двух одинаковых блоков. (INS-14)

**Обратная операция — лучший тест для прямой.** Круг «применить и снять, дерево
обязано вернуться побайтово» нашёл дефект в прямом пути, которого корпус не
видел: там сверяется одно применение. (INS-8)

**У теста на гонку измеряется выявляемость.** Фиксированные сдвиги ловили дефект
в 2 прогонах из 6; сдвиги долями от замеренной длительности — 6 из 6. Тест,
зелёный при сломанном коде чаще, чем красный, охраняет ноль. (INS-6)

**Тест, упавший ровно по таймауту, обвиняет не тот код.** Свой сервер в процессе
теста и `execSync` несовместимы: цикл событий занят, отвечать на запрос некому —
четыре ложных падения по 60 с выглядели как «правка не сработала». (INS-18)

**Шелл посреди теста проверяет шелл.** `--why "$(printf 'one\ntwo')"` на Windows
приезжает литералом: тест был зелёным на двух системах из трёх не по той
причине. Разбор аргументов зовётся напрямую. (INS-10)

**Сюита на macOS не видит дефектов, зависящих от реализации `diff`.** `create` не
работал в изолированной раскладке нигде, кроме macOS: с Apple diff тест зелёный, с
GNU — красный. Правку, задевающую `create`, гонять обоими — `skills/verify`. (INS-11)

**Правка, сужающая работавшее, зелёной сюитой не ловится.** Тесты пишутся под
новое поведение, мутации проверяют внесённое, а не отнятое. Два регресса за одну
задачу нашёл `git worktree add … main` и один сценарий двумя CLI. (INS-16)

**«Команда не упала» — это не «команды сходятся».** Строка «apply, status и rebase
сходятся» держалась на трёх нулевых кодах выхода и пропустила три дефекта. Круг:
первая команда записала — вторая обязана это найти и назвать тем же именем. (INS-17)

**Пропущенный тест перечитывается как вопрос** «точно ли платформа не может
этого наблюдать?». В одном случае из трёх ответ был «может», и за ним стояла
ошибка. (INS-2)

**Красный тест на одной системе из трёх — сперва вопрос «а обещали ли мы это?».**
Тест требовал уборки временного каталога, которую `withPristine` после убитого
установщика намеренно не обещает: EBUSY дороже потерянной причины. (INS-19)

**Свежий фикс — такой же кандидат в аудит, как старый код**, особенно если
трогает то же место: две регрессии за день внесены самим циклом работ. (INS-3)

**Каждое утверждение плана проверяется до кода.** За один день три утверждения
брифа оказались неверны в частностях — план задаёт порядок работ, а не факты
о системе. (INS-1)

## Процесс

**Мутацию восстанавливать только из копии в песочнице.** `git checkout <файл>`
уносил незакоммиченную работу дважды. (skills/verify)

**Новая команда — новая строка в дымовом задании `old-bun`.** Сюита на bun 1.0 и
1.1 не идёт (текстовый локфайл и test runner из 1.2), а обещание `engines` их
включает. (TSK-23)

**Исполнитель делает названное дословно и не переносит правила из соседнего кода.**
В первой делегированной задаче пропущены `validatePackageName`, поведение на Windows
и документация команды, число процитировано с чужим знаменателем — шесть зелёных CI. (INS-12)

**Успешный workflow публикации — ещё не версия в реестре.** Первые минуты
`dist-tags.latest` отдаёт предыдущую версию — наблюдалось на обоих выпусках подряд.
Признак — строка `+ bunch-package@X.Y.Z` в логе задания, а не ответ реестра. (NOT-23)

**Ускорение стенда подменило вход, и корпус это поймал за один прогон.** `npm
pack` + tar вместо `npm install` даёт другое дерево: npm переименовывает
`.gitignore` в `.npmignore`, tar — нет. Расхождение вылезло сразу. (NOT-28)

**Корпус гоняется на живом дереве, а не на снимке.** Правка в `src/` посреди
прогона делит его надвое: первая половина кейсов на одном коде, вторая на другом.
Код замораживается на весь прогон, срочное готовится в копии. (INS-13)

**Шарды корпуса не убиваются по слову «corpus».** Командная строка у них — `bun
run.ts <шард> 3`: `pkill -f corpus/run.ts` не совпадает ни с чем, `ps | grep corpus`
отвечает «0», а старый прогон пишет в те же каталоги — 14 «ошибка на» против нуля. (INS-13)

**Числа в README не подправляются на глаз.** Корпусные нормы плавают от того,
сколько пакетов отдал реестр: сравнено бывает 287 или 289 из 292. Устарело —
перемерить и записать вместе с причиной расхождения. (skills/verify)
