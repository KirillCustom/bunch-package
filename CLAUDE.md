# bunch-package

Управление патчами `node_modules` для bun: альтернатива patch-package, опубликована в npm. Команды: `edit`, `create`, `apply`, `status`, `rebase`, `fold`, `reverse`, `retarget`, `import`, `upstream`, `export`.

TypeScript без сборки, запускается bun'ом напрямую; `dist/index.js` собирается только для публикации. Никаких зависимостей во время работы, кроме `diff` на PATH для `create`.

## Горячий минимум

Пять граблей, которые повторялись дороже прочих. Полный список — `.claude/rules/lessons.md`.

1. **Зелёная сюита ничего не доказывает.** 36 зелёных тестов дали 17 поражений на первом корпусе. Доказательства два: корпус и мутация (INS-4, INS-7).
2. **Молчаливый провал — худший класс здесь.** patch-package применяет дописывающий патч трижды и трижды рапортует успех; `bun install` кладёт хунк по номеру строки, не сверяя удаляемое. Наш ответ — отказ и проверка по дереву (NOT-13, NOT-16).
3. **Правка в `node_modules` меняет общий кеш bun, а `apply` сквозь общий стор — чужие проекты.** Перед правкой `edit`, путь проверять разыменованным (NOT-18, TSK-25).
4. **Мутацию восстанавливать только из копии в песочнице.** `git checkout <файл>` уносил незакоммиченную работу дважды.
5. **Числа не подправляются на глаз.** Устарело — перемерить; корпусные нормы плавают от того, сколько пакетов отдал реестр.

## Стандарт проверки

**Зелёная сюита доказательством не считается.** Измерено: при 36 зелёных тестах корпус из реальных патчей дал 17 поражений против patch-package и 0 побед.

- Каждая правка заканчивается **мутацией**: снимаешь правку — тест обязан покраснеть.
- Правки в разборе, применении или откате патчей проверяются **корпусом** из трёх сотен реальных патчей, собранных из публичных репозиториев.
- Порядок, нормы и способ чтения итога — в скилле `verify`. Выпуск версии — в скилле `release`.

Утверждение без измерения не попадает ни в README, ни в заметки к релизу, ни в комментарий. Если число устарело — перемерить, а не подправить на глаз.

## Что нельзя менять не подумав

Побайтовое совпадение деревьев с patch-package после `apply` — обещание проекта; оно проверяется корпусом на каждой правке разбора или применения. Прямое применение кладёт строку из патча как есть, даже когда это заносит LF в CRLF-файл: так делает patch-package. Откат — другое дело, там мы восстанавливаем переводы строк по файлу.

Второе обещание: **мы не пишем за пределы проекта**. Путь внутри проекта по написанию может вести в общий стор bun — проверять разыменованным.

## Где какое знание

| Вопрос | Где смотреть |
|--------|--------------|
| Что уже решали, измеряли и отвергали? | mIOnika, `projectId: "bunch-package"` — порядок в `.claude/rules/mionika.md` |
| На чём уже обжигались? | `.claude/rules/lessons.md` |
| Чем доказывать правку? | `.claude/skills/verify` — корпус и мутация |
| Как выпустить версию? | `.claude/skills/release` |
| Кто должен делать задачу? | тег модели у задачи — критерии в `.claude/rules/mionika.md` |
| Выполнить задачу на модели из тега? | `/task TSK-NN` → агент `task-runner` |
| Нашёл новые грабли — куда? | `/lesson` |

Решения с отвергнутыми альтернативами, измеренные факты, уроки и задачи — в mIOnika. В репозитории их нет. Сессию стоит начинать с `list_tasks` и `list_atoms`, иначе контекст добывается заново.

Комментарии в коде — по-русски и объясняют **почему**, а не что: какой отказ они предотвращают, на чём это измерено. Комментарий, пересказывающий соседнюю строку, здесь лишний.

## Ход работы

Ветка → коммиты → PR → шесть проверок CI → merge → удалить ветку с обеих сторон. Прямо в `main` не коммитить.

- Сообщения коммитов — по-английски, повествовательные: что было не так, что стало, чем подтверждено.
- Тела PR — по-русски, с таблицами измерений «было / стало».
- Одна ветка — одна тема. Исправление поведения не прячется внутри рефакторинга.
- У задачи в mIOnika есть тег модели-исполнителя; задача без тега не заводится.

## Рабочее окружение

- Временные файлы — в песочницу сессии, не в репозиторий и не в `/tmp`.
- `bun test` держит песочницу в `.test-sandbox-<pid>`; параллельные прогоны друг другу не мешают.
- CI гоняет сюиту на Linux, macOS и Windows плюс дымовые задания на bun 1.0, 1.1 и 1.2 — `engines` обещает `>=1.0.0`. Новая команда — новая строка в дымовом задании.
- Локальный `diff` на macOS — Apple, в CI — GNU, и они расходятся. Правку, задевающую `create`, гонять ещё и `PATH=/opt/homebrew/opt/diffutils/bin:$PATH bun test`.
- Правила лежат в `.claude/rules/`: `lessons.md` (грабли), `mionika.md` (трекер, теги модели).
